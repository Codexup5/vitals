# Styles and accessibility

## 1. Where styles live

`*.module.scss` next to its component; the class is kebab-case by default, in code `styles.cardHeader` (camelCase when the project sets
`CLASS_CASE` in `stylelint.config.mjs` and records it in `docs/deviations.md`). No inline styles, except CSS
variables through `style={{ '--progress': value }}` (eslint). Global rules only in `src/app/styles/`. Another
component's styles are not overridden from outside: either a variant of its API, or it does not fit.

A repeated block of styles becomes a mixin or a global element rule in `app/styles` from the third occurrence, not a
copy.

## 2. Tokens only

Spacing, font sizes, radii and colours are `var(--…)` from `src/shared/styles/tokens.scss` (stylelint; 1–3 px is an
optical correction and may be a number). Illustration sizes (`width`, `height`) may be numbers if they do not repeat. No
suitable token — add a token to the data, not a one-off value. A component uses the semantic level
(`--color-text-muted`), not a raw colour: a theme change is an edit of one file. Raw colours live only in the token data.

The tokens are DTCG 2025.10 data in `src/shared/styles/tokens/`: `config.json` with the layers, the prefix and the names;
`base.tokens.json`; one file per layer, such as `dark.tokens.json` under `prefers-color-scheme`. `tokens.scss` is
generated by `pnpm tokens` and never edited; `pnpm tokens:check` fails a stale one. Each token states its role in
`$extensions.kit`, on itself or on its group. A value the format cannot hold (`round()`, `color-mix()`, a gradient) is a
composite in a hand-written file of `src/shared/styles` over the generated tokens. A missing token is added to the data.
A project without `config.json` has the build and the design checks off.

Kit has no UI kit: the project brings its own. Interface details are components in `shared/ui` built on tokens;
behaviour and accessibility come from ready primitives (Radix, React Aria), not hand-written keyboard logic.

## 3. Breakpoints

Mobile-first: base styles are for the narrow screen, media queries go up (`@media (width >= …)`). Check on mobile first
(Playwright runs both screens).

## 4. Accessibility — the required minimum

- Anything interactive is a native element: `button` for an action, `a href` for navigation. There is no `div` with
  `onClick`. Interactive elements are not nested inside interactive elements.
- Visible focus — one global `:focus-visible` rule; `outline: none` without a replacement is a gross error.
- A field has a real `label`; its error is linked through `aria-describedby`, the field is marked `aria-invalid`.
- An error is not conveyed by colour alone. Contrast and target sizes are the design rules of §6, judged on the tokens
  (text 4.5:1, touch target ≥ 44×44 with `--touch-target`).
- A loading state is `aria-busy`, a screen error is `role="alert"`.

Automatic checks catch about a third of the problems: walk the key scenario once with the keyboard only. The checklist is
the `accessibility` skill.

## 5. Motion and performance

- A screen appears at once; a transition keeps the previous screen until the new one is ready. Skeletons are static.
- Animation only where it explains an action; all of it respects `prefers-reduced-motion` (a global block in
  `global.scss`).
- `key` is a stable id, not an index. A list longer than ~100 rows is virtualized.
- Screens are lazy chunks (`lazyRouteComponent`); a route imports nothing from a page statically, or the page lands in
  the initial chunk. The initial JS budget is `pnpm size`.
- Memoization by measurement, not "just in case"; composition through `children` is cheaper than `memo`.

## 6. Design rules

The design rules judge the token data, not the CSS that uses it: `pnpm tokens:check` resolves every theme and pointer
context and tests each token by its role. A violation fails `pnpm verify`; a warning is a hint, and `pnpm tokens:check
--warnings` lists them.

| Id                     | Rule                                                                                                                                         | Level     | Source                                                  | Checked by                     |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | --------- | ------------------------------------------------------- | ------------------------------ |
| `design/grid`          | A token of role space, size or target is a multiple of 4 px at a 16 px root; 1–2 px only for lines and optical corrections                   | violation | Material 3 layout, the 4 dp grid                        | `pnpm tokens:check`            |
| `design/lh-unitless`   | A line height is a number: a token of role line-height has `$type` number, and a `line-height` declaration has no unit                       | violation | WCAG 2.2 SC 1.4.4 and 1.4.12; CSSWG #11636              | `pnpm tokens:check`, stylelint |
| `design/lh-grid`       | Font size × line height of a line-height token is a multiple of 4 px at a 16 px root, within 0.01 px; a one-line role (`oneLine`) only warns | violation | Material 3 type scale; the user, 2026-10-17             | `pnpm tokens:check`            |
| `design/contrast-text` | In every theme every text token reaches 4.5:1 on every surface it meets, a `large` one 3:1; an `incidental` one is exempt                    | violation | WCAG 2.2 SC 1.4.3                                       | `pnpm tokens:check`            |
| `design/contrast-ui`   | In every theme every ui token (a field boundary, a focus ring, a meaningful icon) reaches 3:1 on every surface it meets                      | violation | WCAG 2.2 SC 1.4.11                                      | `pnpm tokens:check`            |
| `design/apca`          | The APCA contrast, absolute Lc, reaches 75 for text, 60 for large text and 45 for ui                                                         | warning   | APCA 0.0.98G, a hint outside WCAG; WCAG wins a conflict | `pnpm tokens:check --warnings` |
| `design/target-fine`   | A target token is at least 24 px with a fine pointer                                                                                         | violation | WCAG 2.2 SC 2.5.8                                       | `pnpm tokens:check`            |
| `design/target-coarse` | A target token is at least 44 px where any pointer is coarse (the layer with `pointer` coarse, emitted under `@media (any-pointer: coarse)`) | violation | Apple HIG Buttons (44×44 pt); the user, 2026-10-17      | `pnpm tokens:check`            |

An id is `design/<kebab-name>`, unique and never reused for another rule. A finding starts with its level and its id
(`violation design/grid — space.1: …`). A new rule is a new row here, an entry in `RULES` of
`tooling/design/rules.mjs` and a name in `docs/gates.md`; `tooling/design/rules-table.test.js` keeps them in step.
