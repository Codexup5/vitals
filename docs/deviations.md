# Deviations

Deliberate deviations from the brief and from the canon of the user's projects, each with its reason. No marks in the
code, only here. If one repeats, the canon changes, not the code.

| Where                                                   | From what                                                     | Why                                                                                                                                                                                                                                                                                                         | Decision made        |
| ------------------------------------------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| `crates/vitals-ui`: Leptos to WebAssembly               | the brief: React + Vite + TypeScript, the kit web-react pack  | the user wants the whole panel in Rust. Leptos keeps the Tauri window, HTML and SCSS, so the design, the tokens and accessibility carry over; the core is untouched. Slint and egui were weighed: they drop HTML, and egui has almost no screen reader support                                              | 2026-10-27, the user |
| `kit.json`, no `kit-lock.json`                          | the kit web-react pack with its JS gates                      | the gates of the kit hooks are the Rust ones (rustfmt, clippy native and wasm, `cargo test`, `cargo xtask check`); `create-kit update` has no Rust pack to bring, so the lock is gone                                                                                                                       | 2026-10-27, the user |
| `xtask`: the design and style checks                    | the kit's `tooling/design` (Node) and stylelint               | ported to Rust with the same rule ids and bars; it builds the same `_tokens.scss` byte for byte. The APCA hint (a warning, never a gate) is not ported                                                                                                                                                       | 2026-10-27, the user |
| no screen scenario tests                                | the kit: Testing Library + MSW scenarios through the whole app | the view models (`views/`) carry the logic and have `cargo test` cases; the markup is checked live in the panel. The e2e of the cleanup (tauri-driver against a fixture, `VITALS_E2E_ROOT` in a debug build) is written but not in the repository yet: Claude may not download msedgedriver nor build a crate with new dependencies (`ureq`); it waits for the user's decision | 2026-10-28, open     |
| `VITALS_E2E_ROOT` (debug builds only)                   | the panel reads only the real folders of the PC              | the e2e scenario must clean a fixture, never the PC: in a debug build the variable points the home, `%TEMP%`, the Windows temp, AppData and the code roots under one folder. A release build compiles the switch out (`app_paths::e2e_root`)                                                                 | 2026-10-28, Claude   |
| `cleanup`: compacting a WSL or Docker disk is by hand   | the brief, §3: compacting VHDX is a review item                | it needs Docker and WSL stopped and an admin `Optimize-VHD` or diskpart; a panel that stops them on its own breaks running work. The row gets no checkbox, the preview says how to do it                                                                                                                      | 2026-10-28, Claude   |
| `crates/vitals-ui/tokens`                               | a base light theme with a dark layer                          | Catppuccin Mocha is the base (the brief, §4), Latte a layer on `:root[data-theme=light]`. The fine target is 32 px (24 px minimum), 44 px under a coarse pointer          | 2026-10-27, the user |

| `updates`: an installer asks for admin rights itself  | the brief, §1 p.10: an admin action is `vitals.exe --elevated` | winget runs as the user and an installer that needs admin rights raises its own UAC prompt; a "No" there fails that package only (`Declined` in the result). Wrapping winget in `--elevated` would run every package as admin, user-scope ones included | 2026-10-28, Claude   |
| `updates`: BIOS is shown, not linked                    | the brief, §1 p.9: BIOS "by a link"                           | the panel cannot know the board maker's support page; a web search link would send the board model out of the PC. The screen shows the board, the firmware version and date, and says the update is manual | 2026-10-28, Claude   |
| `updates`: winget's table, not JSON                     | a structured answer                                           | winget 1.29 has no JSON output and the WinGet PowerShell module is not installed by default; the table is read by where its titles start (any language), with wide letters counted as two cells. A footer line is told apart by its id and source having no space | 2026-10-28, Claude   |
| `runners`: runners are found by their folders         | a list of repositories in the settings                         | the runners of a repository are asked of GitHub when a `C:\actions-runner*` folder of this PC is configured for it; runners in containers (kit-linux) show through the repository of a local one. | `runners`: the modes stop Docker Desktop and WSL whole  | stopping only the containers of chosen projects               | the modes repeat `mode-gaming.ps1` and `mode-coding.ps1` of the brief §5: memory comes back only when the WSL VM stops. "Gaming" asks once more in place of its button and names how many containers stop | 2026-10-28, Claude   |
| `network`: what leaves the PC                          | the brief, §1 p.14: out only the user's Telegram and the Vitals update check | the brief's own network module needs two more, both without data of the user: ICMP echo to `1.1.1.1` every five minutes (the internet line of the latency chart), and the speed test to `speed.cloudflare.com` only on its button (zeros up, nothing about the PC) | 2026-10-28, Claude   |
| `network`: stage 6 in two PRs                           | one PR per stage                                               | 6a: adapters, latency, loss and jitter, the speed test. 6b: the devices of the network (ARP, ping sweep, names, maker by MAC) and "new device". | `network`: round trips in whole milliseconds            | sub-millisecond latency to the router                          | `IcmpSendEcho` counts whole milliseconds and needs no admin rights; a raw socket would give microseconds only to an admin. | `network`: names without mDNS                          | the brief, §1 p.11: names by mDNS and NetBIOS                  | a name comes from Windows' own resolver (the router's DNS, LLMNR, NetBIOS) through `GetNameInfoW`; an mDNS client would be a new dependency or a hand-written DNS parser. Most home devices show their maker instead; mDNS can follow | 2026-10-28, Claude   |
| `src-tauri/data/oui.tsv`: 1 MB of data in the repository | data fetched at run time                                     | the maker by MAC needs the IEEE MA-L registry; fetching it would send traffic out, so it ships in the exe (about 1 MB). `cargo xtask oui <oui.csv>` rebuilds it from `https://standards-oui.ieee.org/oui/oui.csv`; the legal form of a name is dropped | 2026-10-28, Claude   |
| `startup`: stage 7 in two PRs                            | one PR per stage                                               | 7a: the programs of the Run keys and the Startup folders, their cost, publisher and signature, on and off. 7b: the services, with the start type kept for the way back. Like 3a/3b and 6a/6b | 2026-10-28, Claude   |
| `startup`: turning off is Task Manager's mark            | the brief, §1 p.15: off with a one-click way back             | the panel writes the `StartupApproved` value Task Manager writes (`03` and the time); the Run value, the shortcut and the program stay, so "Turn on" (`02`) is the way back and Task Manager shows the same state. No log of its own: Windows keeps the time it went off | 2026-10-28, Claude   |
| `startup`: the cost of a program is Windows' own trace  | a boot time measured by the panel                              | Windows keeps `wdi\LogFiles\StartupInfo\<SID>_StartupInfo*.xml` for Task Manager, readable without admin rights: the CPU and disk of every process in the first two minutes of a sign-in. The panel sums a program and the processes it started, averages the sign-ins it ran in and applies Task Manager's bars (1 s / 3 MB, 300 ms / 300 KB) | 2026-10-28, Claude   |
| `startup`: tasks of the scheduler and Store startup tasks are not listed | every way a program starts at sign-in              | 7a covers the Run keys (the user's, every user's, 32-bit) and both Startup folders, what Task Manager lists for desktop programs. A logon task of the scheduler needs its COM API or `schtasks` XML; stage 8 retires the OLEGPC tasks through it and can list them then | 2026-10-28, Claude   |
| `startup`: a part of Windows is told by place and signer | a list of protected names                                     | a program in `%SystemRoot%` that no other maker signed (Microsoft's signature, a catalog's or none) is view only, in the panel and again in the elevated process; the Realtek service in `DriverStore` is signed by Realtek and can be turned off. An alias of a Store app is said to be one: `WinVerifyTrust` cannot read it | 2026-10-28, Claude   |
| `services`: "off" is a manual start, never disabled      | the brief, §1 p.15: services turned off with a one-click way back | a disabled service breaks the program that needs it; a manual one starts when that program asks. The start type it had (delayed or not) is kept in `service_changes` and "Restore" sets it back; the elevated side refuses `Disabled` whatever it is asked | 2026-10-28, Claude   |
| `services`: Microsoft's are told by the signer           | the brief, §1 p.15: Microsoft's services view only             | a service is Microsoft's when its file (the DLL of an `svchost` one) is signed by Microsoft, or lies in `%SystemRoot%` with no other maker's signature, or is unknown. Defender, Edge Update, WSL, Visual Studio's are view only; NVIDIA, Realtek, AMD in `DriverStore` are their makers'. The elevated process checks it again | 2026-10-28, Claude   |
