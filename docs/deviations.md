# Deviations

Deliberate deviations from the brief and from the canon of the user's projects, each with its reason. No marks in the
code, only here. If one repeats, the canon changes, not the code.

| Where                                                   | From what                                                     | Why                                                                                                                                                                                                                                                                                                         | Decision made        |
| ------------------------------------------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| `crates/vitals-ui`: Leptos to WebAssembly               | the brief: React + Vite + TypeScript, the kit web-react pack  | the user wants the whole panel in Rust. Leptos keeps the Tauri window, HTML and SCSS, so the design, the tokens and accessibility carry over; the core is untouched. Slint and egui were weighed: they drop HTML, and egui has almost no screen reader support                                              | 2026-10-27, the user |
| `kit.json`, no `kit-lock.json`                          | the kit web-react pack with its JS gates                      | the gates of the kit hooks are the Rust ones (rustfmt, clippy native and wasm, `cargo test`, `cargo xtask check`); `create-kit update` has no Rust pack to bring, so the lock is gone                                                                                                                       | 2026-10-27, the user |
| `xtask`: the design and style checks                    | the kit's `tooling/design` (Node) and stylelint               | ported to Rust with the same rule ids and bars; it builds the same `_tokens.scss` byte for byte. The APCA hint (a warning, never a gate) is not ported                                                                                                                                                       | 2026-10-27, the user |
| no screen scenario tests                                | the kit: Testing Library + MSW scenarios through the whole app | the view models (`views/`) carry the logic and have `cargo test` cases; the markup is checked live in the panel. The e2e of the cleanup (tauri-driver against a fixture, `VITALS_E2E_ROOT` in a debug build) is written but not in the repository yet: Claude may not download msedgedriver nor build a crate with new dependencies (`ureq`); it waits for the user's decision | 2026-10-28, open     |
| `VITALS_E2E_ROOT` (debug builds only)                   | the panel reads only the real folders of the PC              | the e2e scenario must clean a fixture, never the PC: in a debug build the variable points the home, `%TEMP%`, the Windows temp, AppData and the code roots under one folder. A release build compiles the switch out (`app_paths::e2e_root`)                                                                 | 2026-10-28, Claude   |
| `cleanup`: compacting a WSL or Docker disk is by hand   | the brief, §3: compacting VHDX is a review item                | it needs Docker and WSL stopped and an admin `Optimize-VHD` or diskpart; a panel that stops them on its own breaks running work. The row gets no checkbox, the preview says how to do it                                                                                                                      | 2026-10-28, Claude   |
| `crates/vitals-ui/tokens`                               | a base light theme with a dark layer                          | Catppuccin Mocha is the base (the brief, §4), Latte a layer on `:root[data-theme=light]`. Latte `blue` and `red` are darkened to `#1c5ce0` and `#c80d36`: the palette values give 4.03:1 and 4.46:1 on mantle, under 4.5:1. The fine target is 32 px (24 px minimum), 44 px under a coarse pointer          | 2026-10-27, the user |
| `crates/vitals-ui/index.html`: `data-wasm-opt-params`   | Trunk's default wasm-opt call                                 | Rust 1.87+ emits post-MVP opcodes (bulk memory and others); wasm-opt validates them only when told to                                                                                                                                                                                                       | 2026-10-27, Claude   |
| `updates`: an installer asks for admin rights itself  | the brief, §1 p.10: an admin action is `vitals.exe --elevated` | winget runs as the user and an installer that needs admin rights raises its own UAC prompt; a "No" there fails that package only (`Declined` in the result). Wrapping winget in `--elevated` would run every package as admin, user-scope ones included | 2026-10-28, Claude   |
| `updates`: BIOS is shown, not linked                    | the brief, §1 p.9: BIOS "by a link"                           | the panel cannot know the board maker's support page; a web search link would send the board model out of the PC. The screen shows the board, the firmware version and date, and says the update is manual | 2026-10-28, Claude   |
| `updates`: winget's table, not JSON                     | a structured answer                                           | winget 1.29 has no JSON output and the WinGet PowerShell module is not installed by default; the table is read by where its titles start (any language), with wide letters counted as two cells. A footer line is told apart by its id and source having no space | 2026-10-28, Claude   |
| `.claude/settings.json` still allows `pnpm` commands    | the permissions match the tools                               | Claude may not edit its own permissions; the user replaces the `pnpm` lines with `cargo fmt*`, `cargo clippy*`, `cargo test*`, `cargo xtask*`, `trunk build*`, `cargo tauri build*` and drops `typescript-lsp`                                                                                              | open, the user       |
