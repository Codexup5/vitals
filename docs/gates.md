# Gates

A rule without an automatic check does not exist. Each rule here is checked by a machine, and its test shows that the
check catches the violation and lets the correct form pass. A canon rule missing here is a candidate for a check or for
removal. A new rule lands with its row, its check and its test in one commit.

## Checks on the running app

These run in the browser, on the built app, and need the Playwright browsers: `pnpm test:e2e` runs them on the project
`prod` (the preview of `pnpm build`, Pixel 7).

- **The content security policy in the browser** — `e2e/prod/csp.spec.ts`: `/` loads with no `securitypolicyviolation`
  event and no console message naming Content Security Policy; the response header equals the `csp.json` header (the
  preview sends it; a deployed URL is judged by its host) and, in `enforce`, the build meta equals the policy without
  `frame-ancestors`; in `report-only` there is no meta. Checked by the spec; the policy itself by `pnpm csp:check`.
- **The Web Vitals budgets on the built app** — `e2e/prod/web-vitals.spec.ts` on the project `prod`: the budgets of
  `e2e/prod/web-vitals-budgets.ts` (LCP ≤ 2500 ms, CLS ≤ 0.1, INP ≤ 200 ms when reported) hold for `/` after a click on
  the filter, measured by the `web-vitals` library the test injects, not by the app. The provider seam is
  `initWebVitals` of `src/app/monitoring/web-vitals.ts`: a project with another provider replaces its body and keeps
  the budget gate.
- **The visual baseline** — `e2e/visual/reference.spec.ts` with `e2e/__screenshots__/`: the main region of the user
  list (light and dark), the details of the first user and the form with its required-field messages, on Pixel 7 and
  Desktop Chrome — 8 PNGs. They are rendered only in the Playwright image on Linux (`pnpm test:visual`, rewritten by
  `pnpm test:visual:update`; the config throws off Linux), and the CI job `visual` runs them on every PR.
