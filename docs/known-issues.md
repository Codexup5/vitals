# Known traps

Recurring problems that are easy to hit a second time: symptom → cause → how to avoid it.

| Symptom                                                                        | Cause                                                                                                                       | How to avoid it                                                                                                                      |
| ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `cargo tauri build` fails "failed to remove file … vitals.exe: Access is denied" | the panel is still running from `target\debug` (it hides to the tray on close)                                              | quit it from the tray, or `taskkill /IM vitals.exe /F`, then build                                                                   |
| The window is empty: the background shows, nothing else                        | the WebAssembly did not load; 2026-10-27: the CSP had no `'self'` in `connect-src`, and the fetch of the `.wasm` was blocked | keep `connect-src 'self' ipc: http://ipc.localhost` in `tauri.conf.json`; to read the console, add `"additionalBrowserArgs": "--remote-debugging-port=9222"` to the window for a local build only |
| clippy or `cargo test` of `src-tauri` fails: `frontendDist` does not exist      | `tauri::generate_context!` embeds `crates/vitals-ui/dist`, which a fresh checkout lacks                                     | `trunk build` in `crates/vitals-ui` first (CI does)                                                                                  |
| `trunk build --release` fails in wasm-opt: "memory.copy operations require bulk memory" | Rust 1.87+ emits post-MVP opcodes; wasm-opt validates them only when told to                                                 | keep `data-wasm-opt-params` with the `--enable-…` flags in `crates/vitals-ui/index.html`                                              |
| Cargo resolves Leptos 0.8.3 and its macros fail to build against `syn`          | the resolver respects `rust-version`; at 1.85 it picks old Leptos releases                                                  | keep the workspace `rust-version` at 1.90 or above                                                                                   |
| A `view!` attribute like `disabled=page >= count` silently loses its value     | the macro reads `disabled=page` and takes `>` as the end of the tag                                                         | wrap a comparison in braces: `disabled={page >= count}`                                                                              |
| A junction is not deleted; the cleanup counts it as busy                       | `Metadata::is_dir` is false for a junction (it reads as a link), so `remove_file` was tried on a directory entry              | test the directory attribute (`FILE_ATTRIBUTE_DIRECTORY`) of a link, then `remove_dir` removes the link itself (`cleanup::execute`)     |
| The window dies: "Tried to access a reactive value that has already been disposed" | an async answer writes a signal of a view that a refresh of the screen already replaced                                       | keep the state an answer writes on the page, outside the reactive closure; write it with `try_set` in the future                         |
| A debug panel gets no `--remote-debugging-port`; port 9222 refuses       | another Vitals (the desktop shortcut) runs WebView2 on the same profile and a second start joins it; and Tauri passes its own browser arguments, so `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` alone is ignored | for a local build only: `"additionalBrowserArgs": "--remote-debugging-port=9222"` on the window, plus `WEBVIEW2_USER_DATA_FOLDER=<scratch>` for a profile of its own; take the line out before a commit |
| An upgrade fails with `0x8A150011`                                          | the maker replaced the installer under the winget manifest (Ubisoft Connect, Waves Central on 2026-10-28); winget refuses a file whose hash differs | never `--ignore-security-hash`: the result says to update from the maker's site or wait for the manifest (`UpgradeOutcome::HashMismatch`) |
| A footer of `winget upgrade` shows up as a package                          | "1 package(s) have version numbers that cannot be determined…" is long enough to fill every column                          | a package row has an id and a source without spaces (`updates::packages_of`); a fixture with the real footer guards it             |
| A tool that prints a lot hangs until its deadline                           | its stdout pipe filled while the panel waited for the exit before reading                                                   | `process::output` reads stdout on its own thread while it waits                                                                      |
| A Store app (Teams) reads as "signature does not hold"                      | its Run value starts an app execution alias in `%LOCALAPPDATA%\Microsoft\WindowsApps`, a reparse point `WinVerifyTrust` cannot open | tell the alias apart before verifying (`trust::is_app_alias`): the state is `StoreApp`, never `Invalid` |
| A company name ends in garbage ("Spotify Ltd\08…FileDescr")                 | `VerQueryValueW` returns a length some files count in bytes, not characters                                                   | cut a version string at its first NUL (`trust::windows::version_text`)                                |
| After an update the collector or the sampler is off: "table … already exists" in the log | the threads and the commands open the database at once and each applied the new migration; a deferred `BEGIN` let two of them read the same version | each step runs under `BEGIN IMMEDIATE` and reads the version again inside it, and every connection waits for a writer (`busy_timeout`); a test opens six at once |
| A line that says how an action went vanishes at once                       | the action reads the status again, which redraws the block, and the signals made inside it go with it                          | keep that state on the page and hand it down (`ui::settings`), as the cleanup does                                                      |
| A screen that polls keeps the core busy while nobody looks at it              | Tauri's `hide` and a minimized window leave the WebView2 page visible: `document.hidden` stays false and its timers run on | the window closes, not hides, when it goes to the tray (its WebView2 ends with it, `show_main_window` builds it again); a command that works for a poll still asks `is_visible` and `is_minimized` (`commands::sensors`) |
| Every reading of the sensors takes a second longer without LibreHardwareMonitor | Windows retries a TCP connection to a closed port of this PC for about two seconds rather than refusing it at once | a connection to `127.0.0.1` gets a short timeout of its own (`sensors::lhm`, 200 ms): a server there accepts in microseconds |
| A value of LibreHardwareMonitor reads as none, or in Fahrenheit | its `data.json` formats each value in the language of Windows (`61,4 °C`), and `Value` in the unit the user picked | read `RawValue` and `RawMax`, always in Celsius, and take a comma or a dot as the decimal point (`sensors::lhm::number_of`) |
| A setting the Windows UI shows as on reads "can apply" (Game Mode on a fresh profile) | Windows treats an absent value as its default; the optimizer compares the registry, and an absent value is not the target | writing the target is harmless and the revert deletes it again; compare a value, never a toggle in Settings, when checking a reading against the screen |
| A setting done by hand reads as partly done (Start without recommendations on OLEGPC) | the hand change set one of its values (`Start_IrisRecommendations`) and not the other (`Start_TrackDocs`) | an item is done only when every value holds; open "Values" in the row to see which one is missing |
