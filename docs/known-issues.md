# Known traps

Recurring problems that are easy to hit a second time: symptom → cause → how to avoid it. Added to by the `debug` and
`retro` skills.

| Symptom                                                                                  | Cause                                                                                                                                                                                     | How to avoid it                                                                                                                                 |
| ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| A page loads in the start chunk although the route is lazy                               | the route statically imports something from `pages/*` (a schema, a skeleton) - the bundler cannot split a module that is needed both at once and lazily                                   | everything from a page goes only through `lazyRouteComponent`; the URL parameter schema lives in the entity                                     |
| A server field error is not cleared after an edit                                        | the field has no validators of its own, nobody clears `onServer`                                                                                                                          | `listeners: { onChange: ({ fieldApi }) => clearServerError(fieldApi) }` in the form                                                             |
| The list did not update after a mutation                                                 | the invalidation key with concrete parameters did not match the live query                                                                                                                | invalidate the `X_KEYS.lists()` level through the entity's cache event                                                                          |
| MSW: "Failed to register the Service Worker"                                             | there is no `public/mockServiceWorker.js`                                                                                                                                                 | `pnpm exec msw init public`                                                                                                                     |
| No TypeScript diagnostics after an edit, although the `typescript-lsp` plugin is enabled | the plugin needs `typescript-language-server` and `typescript` on PATH; P6 (2026-10-14) found neither on this machine, so the plugin starts no server                                     | `npm install -g typescript-language-server typescript` (a global install is the user's decision), then start a new session                      |
| An e2e assertion on `evaluate` reads `undefined` and can never pass                      | `locator.evaluate` with a string arrow function (`'(el) => …'`) returns `undefined` instead of calling it; e2e strings stand in for functions because `tsconfig.node.json` has no DOM lib | judge the DOM through locator assertions (`toHaveCSS`, `boundingBox`, `toBeAttached`); a string `evaluate` only as an expression (`'window.x'`) |
| A tooling test unrelated to the change times out at 5 s in `pnpm verify`                 | a new tooling test that spawns a CLI or loads a project adds load to the parallel run, and the eslint probes pass the vitest default (2026-10-26: 3 of 6 runs)                            | a describe that runs a CLI, ESLint or a config loader names its timeout (`CLI_TIMEOUT` of `tooling/design/tokens.test.js`)                      |
